# Action Memo：录音豆个人行动纪要

这是一个面向 soundcore Work 3200 黑客松的 MVP。它把录音或对话转写内容整理为当前用户需要处理的行动项，并保留原文依据。

## 能做什么

- 直接粘贴中文对话转写，或上传音频、视频录音
- 生成个人任务清单；明确且有截止时间的任务进入“我的任务清单”，需要确认或补充时间的任务进入“模糊任务清单”
- 用户可以修改模糊任务、补充截止时间并确认归入自己的清单
- 在“任务清单”右上角添加手动待办；我的任务可勾选完成、再次取消完成，展开后可编辑，手动待办也可删除
- 首页进入“录音转写”，选择上传录音或粘贴文字；生成后才能从结果页进入针对当前记录的“个人重点”和“内容记录”
- 首页左上角可修改本机 Demo 的使用身份；这不是登录账号，个人偏好在后台辅助后续分析，不单独展示画像页面
- 识别多人共同负责的任务与跨句出现的截止时间
- 让每条任务回溯到原始说话人和时间戳
- 在网页中确认、修改或忽略任务
- 将转写、任务清单与人工判断保存在本机数据库，并按场景放入“文件夹”；首页最近记录可直接打开
- 可删除单条记录；删除场景文件夹时，其记录会移入默认文件夹，默认文件夹不可删除
- 新建场景文件夹时可填写图标关键词，后台调用图片 API 生成专属图标；生成中或失败时使用预设场景图。文件夹的复制信息、编辑、图标重做和删除统一放在“管理”模式
- 未手动选择场景时，保存前会根据已有文件夹的关键词推荐明确匹配的文件夹；用户确认后才归档，匹配不明确则留在默认文件夹
- 只保留“动作 + 明确对象”的具体任务；模糊的“跟进一下、处理这个”等表述不会进入待办或个人画像
- 未配置 API Key 时仍可打开并查看本地兜底 Demo

## 首次运行

### 1. 克隆项目

```bash
git clone https://github.com/Wanft11/action-memo-demo.git
cd action-memo-demo
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

### 2. 配置自己的 OpenAI API Key

在 Mac 上直接用文本编辑器打开 `.env`：

```bash
open -e .env
```

如果使用 VS Code：

```bash
code .env
```

把文件中的这一行：

```env
OPENAI_API_KEY=""
```

改为自己的 Key：

```env
OPENAI_API_KEY="你的 OpenAI API Key"
```

保存即可。每位队友使用自己的 Key；`.env` 不会被上传到 GitHub。

### 3. 启动 Demo

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

浏览器打开：<http://127.0.0.1:8000/demo>

没有 API Key 时，页面仍会打开并显示兜底示例。真实录音转写和 AI 内容分析需要配置 Key。

手机与电脑连接同一个可信 Wi-Fi 后，在手机浏览器打开 `http://电脑的局域网 IP:8000/demo`。Mac 可用 `ifconfig en0` 查看 `inet` 地址。不要在公共网络开放此 Demo：当前版本没有真正的账号认证，同一台服务上的使用者会共享本机数据库和 API 配置。电脑需要保持运行。

### 快速试跑样本

从首页点击“录音转写”，切换到“粘贴文字”，再点“加载测试转写”，可从 11 份不同场景的样本中选择。每份样本约 10–15 分钟，每轮发言间隔 5–15 秒。测试样本预设本人标为“小万”，其他发言者保留为“说话人 1/2/3”；对话中实际说出口的姓名仍按原话保留。加载样本后会自动选中“小万”，但真实录音目前不具备自动声纹认人的能力，仍需人工确认。预赛样本在 `static/samples/recording-bean-preliminary-meeting.txt`。

### 测试“个人重点”

先生成任务清单，或从首页“最近记录”/文件夹里打开一条已保存的记录，再点击结果页的“个人重点”。输入一个具体问题，例如“技术流程什么时候能给出？”，再点击“生成个人重点”。页面会给出围绕当前记录的回答和原文依据；你也可以在“复查索引”中粘贴一句话或一段原文，定位并复制对应的转写片段。“内容记录”也在同一结果页，不再作为首页全局入口。

### 手动待办

进入“任务清单”，点右上角 `+` 可添加待办和可选截止时间。手动待办会按当前使用身份保存在本机数据库，刷新后仍在；勾选框可标记完成或恢复未完成。录音提取的任务也可勾选和修改，但这类修改只有在该记录保存后才会跨刷新保留。

### 本机文件夹与后台个人偏好

生成任务清单后点击“保存到文件夹”，转写、分析结果、任务确认和文件夹关键词/称呼会保存在本机 `.action-memo/action_memo.db`。底部“文件夹”可进入每个场景并查看记录；在文件夹页面点击“管理”，选中一个或多个文件夹后可复制信息、编辑设置、重做图标或删除。关键词和称呼刷新或重启后仍会保留。个人偏好不单独展示为页面；下一次调用 AI 分析时，后台只检索相关的已确认/已排除任务标题作为辅助上下文，不会上传旧记录全文，也不会覆盖原文中明确的负责人。该目录已被 Git 忽略，修改不会自动上传到 GitHub。

新建文件夹时可填写独立的“图标物件关键词”，不会影响分类；已有文件夹可在“管理”模式选中后点击“图标”，弹窗修改关键词并生成或重做。生成时只向 OpenAI 图片 API 发送**文件夹名称和最多八个图标关键词**；留空时使用场景关键词。每次生成或重试都可能消耗 API 额度。录音、转写和称呼不会用于生成图标。关键词和生成图片保存在本机 `.action-memo/`，不会自动上传到 GitHub。未配置 Key 或生成失败时，页面继续使用仓库中的预设图标，不影响文件夹和记录。可在 `.env` 中用 `OPENAI_IMAGE_MODEL` 调整图片模型；默认值见 `.env.example`。

### 安装团队共享的脱敏测试库

仓库中的 `static/samples/action_memo_demo.db` 是一份脱敏测试数据库，包含两场虚构会议、三个场景文件夹和示例关键词/称呼，不含任何本机真实记录或音频。队友拉取最新代码后，可在项目根目录执行：

```bash
mkdir -p .action-memo
cp static/samples/action_memo_demo.db .action-memo/action_memo.db
```

然后刷新 Demo，从首页左上角设置使用身份为 `演示用户`，打开“文件夹”即可查看和编辑相同的测试文件夹。**复制命令会覆盖本机已有数据库**；如已有自己的记录，请先备份 `.action-memo/action_memo.db`。仓库中的演示库只是共享快照：每个人后续在页面上修改的关键词、称呼和任务仍仅保存在自己的电脑，不会实时同步给队友。如需重新生成仓库版本，执行：

```bash
.venv/bin/python scripts/create_demo_database.py
```

### 安装当前团队测试快照

`static/samples/action_memo_team.db` 是当前本机记录的手动快照，包含四条测试记录、生成结果和七个文件夹设置；没有音频文件。它与上面的脱敏演示库是两个可选测试起点。需要测试同一份记录时，在项目根目录运行：

```bash
mkdir -p .action-memo
cp static/samples/action_memo_team.db .action-memo/action_memo.db
```

刷新 Demo，并在首页左上角将使用身份设为 `小万`。**复制会覆盖已有本机数据库，请先备份。**后续在页面上修改记录、关键词或称呼不会自动同步到 GitHub；只有经过检查并重新提交快照后，队友才能取得更新。真实会议或录音加入本机库后，不要直接重新上传这个快照。GitHub 旧提交也会保留已上传的内容，之后删除文件不能抹去历史版本。

## 团队协作

仓库目前是私有的。先由仓库管理员在 GitHub 的 `Settings → Collaborators` 邀请队友，接受邀请后即可访问和提交代码。

### 在 GitHub 网页直接编辑或上传

适合修改文案、README 或上传小型测试文件：

1. 打开仓库，进入要修改的文件，点击右上角铅笔图标。
2. 修改完成后，在页面底部填写本次修改说明，点击 `Commit changes`。
3. 上传文件时点击 `Add file → Upload files`，把文件拖入页面后提交。

### 在本地修改并推送

适合修改前端、后端或多个文件。每次开始前先同步最新代码：

```bash
git pull origin master
```

修改并保存后，先查看这次会上传什么：

```bash
git status
```

再提交指定文件并推送：

```bash
git add static/index.html
git commit -m "优化任务卡片展示"
git push origin master
```

改后端时，把 `static/index.html` 换成实际修改的文件路径，例如：

```bash
git add app/services/meeting_analyzer.py
git commit -m "改进待办提取逻辑"
git push origin master
```

多人同时改同一个文件时，先 `git pull origin master` 再开始修改；每次提交只包含一件清晰的小修改，之后更容易合并和回退。

### 测试录音文件

可在项目里新建 `samples/` 文件夹，存放允许团队共享的测试音频。不要上传包含隐私内容的真实会议录音，也不要上传 API Key、`.env` 或个人账号信息。

## 接口

- `GET /api/health`：检查服务是否启动。
- `POST /api/meetings/analyze`：接收 `current_user`、`transcript`、可选 `audio` 和 `markers`，返回内容分析结果。
- `POST /api/meetings/focus`：接收 `current_user`、`transcript` 和 `focus_query`，返回个人重点及可复查的原文依据。
- `GET /docs`：打开接口文档。
