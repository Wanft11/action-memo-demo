## 二、方案成果展示

### 1. 赛题理解

我们选择智能录音赛道。我们理解，录音设备的价值不应停留在“把声音保存下来”或“把声音变成文字”，而应帮助用户在真实交流结束后快速找到对自己有用的信息，并采取行动。

目标用户是经常参加临时工作沟通、客户交流、家校沟通、面试、学习讨论及家庭安排的人。交流往往发生得快、信息分散；用户当时不方便持续记笔记，之后又需要从长录音中重新寻找承诺、时间、决定和个人相关信息。传统逐字稿保留了内容，却仍把筛选和整理的负担留给用户。

因此，我们把问题聚焦为：**如何利用录音豆采集的对话和用户主动标记的重点，结合具体使用场景，可靠地提取个人下一步行动与值得记住的信息，并让用户能核对依据、修正结果。**

### 2. 具体方案说明（突出 AI 能力）

产品定位为“录音豆个人行动助手”。用户上传录音或粘贴转写，确认当前使用身份和场景文件夹后，系统生成个人任务与重点信息。输出以简短待办为主，用户展开后能看到来源时间、说话人和原文；不确定的任务进入待确认清单，由用户认领、修改或排除。

#### 功能一：从录音豆重点片段提炼可行动信息

**做什么：** 用户在交流中按压录音豆标记重点。系统围绕标记前后约 45 秒的上下文，提炼该段谈清的事项、与用户有关的行动、时间或条件，并附上原文依据。用户可以将明确行动加入待办，也可以回听、收藏或分享重点。

**怎么做：** 音频由语音识别服务转成文本；当输入转写带有时间戳和说话人标签时，分析流程会保留这些信息。重点标记作为结构化事件传入流程，分析模型围绕标记附近的语句提炼重点，并从编号后的原文中引用证据，后端校验引用后返回前端。原文转写仍可查看，但不作为主要结果呈现。

**当前原型边界：** 页面、标记数据结构和前后文分析逻辑已实现，带时间戳的演示样本可以展示标记片段。目前通过原型表单/样本传入标记时间，尚未接入 Work 3200 官方设备 SDK 或验证真实设备的自动同步链路。当前音频转写调用返回文本，不保证逐句时间戳和说话人分离；这两项以及设备联调需要后续完善，不作为当前已完成能力宣称。

#### 功能二：个人待办与可核对的原文证据

**做什么：** AI 从整段交流中提取“动作 + 对象”明确的任务，结合说话人、上下文和截止时间形成个人任务清单。明确任务可直接进入“我的任务”；负责人或任务归属有歧义的候选项进入模糊清单，用户可以确认、标为非本人任务，或修改任务内容和时间。任务可勾选完成；有明确日期和时间的任务可以导出到日历。

**怎么做：** 后端解析转写中已有的时间戳和说话人标签，再由大模型按结构化 JSON 输出行动项和原文编号。规则层负责校验负责人、期限、重复项和引用来源，并将每条任务映射回对应原句。没有配置 API 时，文本仍可使用本地规则分析；本地规则仅作为演示兜底，结果会标明其能力限制。

#### 功能三：场景文件夹与跨记录提问

**做什么：** 用户可把记录放入“客户沟通”“家庭生活”“学习计划”“面试 / 求职”等文件夹，并维护场景关键词、称呼和关注方式。例如客户沟通关注需求、异议、报价承诺和下一步；家庭生活关注时间安排、采购、陪伴和健康提醒。用户可以针对一个文件夹里的多条历史记录提问，例如“客户上次最在意什么？”或“最近几次面试里我反复被建议改善什么？”，答案会标出对应记录标题和原文片段。

**怎么做：** 文件夹设置和记录保存在本机 SQLite 数据库。提问时后端只汇总选中文件夹中的近期记录，给每条转写加上记录标题和原时间戳，再交给分析模型回答；模型需以这些记录为依据返回引用。场景关键词也可用于建议归档。用户对任务的确认和排除反馈会作为后续任务筛选的辅助参考，不能覆盖当前原文中明确的负责人或表述。

#### 端到端流程

```text
录音豆采集 / 用户导入录音
        ↓
语音转文字（保留时间戳与说话人标签）
        ↓
结合用户身份、场景文件夹及设备重点标记进行分析
        ↓
个人待办 / 场景重点 + 可回查的原文依据
        ↓
用户确认、修改或排除 → 保存记录与反馈 → 后续分析参考
```

原型技术结构：移动端适配的网页前端 → FastAPI 接口 → 语音识别与大模型分析 → SQLite 本地记录库。AI 分析模型、语音识别模型和文件夹图标生成模型通过配置分别调用；API Key 放在服务端环境变量中。当前演示没有账号认证，数据仅用于单机原型，不应作为多人线上服务部署。

### 3. 方案价值与预期效果

产品把用户复盘一段交流的主要动作，从“重听或搜索长逐字稿”，转为“先看个人行动和场景重点，必要时打开原文核对”。这有望减少遗漏承诺、错过时间安排和重复翻找录音的成本。对客户沟通，可帮助整理需求、异议与后续承诺；对家庭、学习和求职场景，可把分散在对话中的安排、建议与材料要求留下来。

预赛阶段把价值验证目标设为：用户能否在 1 分钟内找到一段交流中与自己最相关的行动；任务是否能被原文证据支持；用户是否能快速纠正负责人不明或归属错误的候选任务。上述是待实测的验证指标，不是已取得的效果数据。后续可用不同场景的测试转写记录任务识别准确率、证据可核对率、用户确认/排除比例和完成一轮整理所需时间。

24 小时开发内可演示的原型范围：移动端网页、录音上传或文字粘贴、转写分析、个人任务确认与编辑、带时间戳测试转写上的录音豆标记片段分析、场景文件夹、文件夹内跨记录提问、来源回查和日历文件导出。真实设备 SDK 联调、稳定的逐句时间戳与说话人分离、生产级账号体系、云端多用户同步和量化效果验证不属于当前原型完成范围。

### 4. 方案优势 / 创新点

1. **从“会议纪要”转向“个人行动”。** 不要求用户重新阅读整篇摘要，而是优先回答“我需要做什么、我需要记住什么”。
2. **把硬件重点标记变成理解线索。** 用户按压产生的时间点用于分析前后语境，AI 围绕用户主动关注的片段提炼信息，避免把标记仅做成逐字稿上的装饰。
3. **场景和个人反馈共同参与分析。** 文件夹关键词、称呼和关注方式帮助模型理解同一用户在客户、家庭、学习等情境中的差异；人工确认与排除用于逐步改善后续筛选。
4. **结果可回查、可修正。** 每个行动都尽量回到原话与时间戳，模糊任务交给用户确认，降低模型误判被直接执行的风险。
